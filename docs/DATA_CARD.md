# Synthetic data card (Annex E)

| Field | Content |
|---|---|
| Purpose | Exercise personal-data, eligibility and multi-step questions (attendance, results, relaxation what-if, detention) for two programmes, including every boundary the NSUT rules create (clause 11.2 75%, 11.3/11.4 relaxation, 11.6 60% floor). |
| Generator | TODO (team): model name + version used (local Ollama), temperature, number of LLM calls. Raw output: `data/csv_original/` (`manifest.csv` lists the generated row counts). |
| Prompts | TODO (team): add the verbatim prompt to `prompts/student_profiles_prompt.txt`. |
| Schema enforcement | Generated CSVs were checked against Annex C. Mechanical fixes in `scripts/convert_to_annex_c.py` (logged): `students.program` → `programme`; `results.exam_type` actually held the session ("2026 MAY") → `exam_session`; `results.result_type` (REGULAR/SUPPLEMENTARY) → `exam_type`; `pass_marks` dropped (the threshold belongs in `rule_registry`), `max_marks` = 100. Every row is then validated by `app/db/validation.py`, which is shared with the loader. |
| Row counts and distributions | 52 students: B.Tech CSE 28 (batch 2022 = 7, 2023 = 8, 2024 = 13) and B.Tech ECE 24 (7 / 8 / 9). 8 courses (4 per programme). 104 attendance rows: 55%–95%, classes held always 40. 103 results: PASS 99, FAIL 2, ABSENT 1, DETAINED 1. Total marks 0–92 overall (PASS rows 70–92, FAIL 39, ABSENT 0, DETAINED 12). CGPA 6.42–9.01. Active backlogs 0–3. |
| Edge cases included | Attendance exactly at 75%: **S1004/CS301** (30/40). One class below: **S1003/CS301** (29/40 = 72.5%, inside the Dean's relaxation). Dean-relaxation range: **S1006/CS301** (70%). Exactly at the 60% floor: **S1052/CS301** (24/40, needs Dean + committee). Below the floor and DETAINED: **S1051/CS301** (22/40, result DETAINED). Marks just below 40: **S1003/CS301** (39, FAIL). ABSENT: **S1006/CS301**. Multiple backlogs: **S1006** (3) and others with 2. CGPA at a placement cut-off: **not applicable**, because the NSUT Placement Policy defines no university-wide CGPA cut-off (criteria are set per company). |
| Validation results | `scripts/validate_synthetic_data.py` → `docs/validation_output.txt`: 0 hard violations after the fixes below. Checks: required columns, ID format, ranges, attended ≤ held, total = internal + external, result consistent with the registry pass mark (when one exists), FK integrity, students with fewer `active_backlogs` than open FAIL/ABSENT results, supplementary attempts after a PASS, attendance in another programme's course, and edge-case coverage driven by `rules_seed.csv`. |
| What the LLM got wrong | (1) Column names and schema drift (above). (2) **S1006** had a SUPPLEMENTARY attempt in CS302, a course they had already PASSED, while their ABSENT course CS301 had none. The attempt was moved to CS301 (`scripts/repair_synthetic_data.py`, R1). (3) No DETAINED student and no student at the 60% floor, so S1051 and S1052 were added deterministically by code (E1/E2). (4) The draft `rule_registry.csv` cited clauses and documents that are not in the corpus (see README, "Rule registry"); those rules were not used. (5) Several students have `active_backlogs` > 0 with no FAIL row. We kept these as plausible (backlogs from earlier semesters not in the data) and list them as a limitation. |
| Known limitations | Only 2 courses per student have attendance and results, and a single exam session (2026 MAY plus one NOV supplementary). Classes held is always 40. CGPA is given, not derived from grades. Backlogs are not fully reconcilable with the results table. Names are placeholders ("Student Alpha"…). No hostel, fee or scholarship records. |
